# Размещение видов и заголовки на листах

[← Работа с Revit MCP](USAGE.md)

`list_sheet_resources` возвращает основные надписи, типы видовых экранов, листы и неразмещённые виды. Необязательный `sheetId` ограничивает листы и проверку размещения выбранным листом.

- `viewportTypes`: ID и имя типа, `showTitle` — исходное значение параметра «Показать заголовок» (0 — нет, 1 — да, 2 — несколько видовых экранов), его отображение `showTitleDisplay`, показ выносной линии, ID, семейство и имя типа заголовка.
- `sheets`: фактические `minXmm`, `minYmm`, `maxXmm`, `maxYmm` из `ViewSheet.Outline`, ширина, высота и ID экземпляра основной надписи. `titleBlockIds` содержит все экземпляры; `titleBlockId` — первый по ID, либо `null`, если основной надписи нет.
- `sheets[].viewports`: ID экрана и исходного вида, `viewportTypeId`, масштаб, центр, `boundsMm` без заголовка и отдельный `labelBoundsMm` (`null` для отсутствующего заголовка), текст заголовка, смещение и длина линии.
- `unplacedViews`: масштаб, `paperBoundsMm` из `View.Outline` в масштабе бумаги с видимыми аннотациями, `canAddToSheet` и `availableSheetIds`. Возможность размещения проверяется через `Viewport.CanAddViewToSheet` для каждого возвращённого листа. Без существующих листов `canAddToSheet=null`. Ошибки чтения конкретного вида перечислены в `errors`.

Границы и центры ресурсов — абсолютные координаты в системе листа, в миллиметрах. Начало листа может находиться в отрицательных координатах: используйте `min/max`, а не диапазон от нуля до ширины/высоты. `paperBoundsMm` неразмещённого вида относится к локальному пространству бумаги самого вида; окончательное положение и границы экрана возвращает предпросмотр размещения.

## Исходные виды на существующих листах

`preview_place_views_on_sheets` создаёт видовые экраны для исходных видов, проверяет результат Revit и полностью откатывает изменения. Виды не дублируются; их имя, масштаб, шаблон и область обрезки сохраняются.

```json
{
  "placements": [
    {
      "sheetId": 2798849,
      "viewId": 2792781,
      "centerXmm": -250,
      "centerYmm": 400,
      "viewportTypeId": 12345
    }
  ]
}
```

Центры заданы в абсолютных координатах листа. `viewportTypeId` необязателен; без него Revit использует тип экрана по умолчанию. Один пакет содержит 1–50 размещений. Повтор пары лист/вид отклоняется. Размещение одного вида на разных листах допустимо только тогда, когда это разрешает Revit, например для легенды. Спецификации размещаются другими операциями, через `ScheduleSheetInstance`.

Ответ `preview.result.placements` содержит `viewportId`, исходный `viewId`, фактический тип, масштаб, центр, границы экрана и заголовка после регенерации и завершения пробной транзакции. Проверьте компоновку и передайте `planId` в `apply_place_views_on_sheets`. Используйте постоянные ID из `result.placements` ответа apply: ID новых экранов в preview временные.

Операция размещает вид в запрошенной точке; пересечения и выход за рамку оцениваются по возвращённым границам. Ошибка любого размещения откатывает весь пакет. Apply проверяет тот же документ и его ревизию; изменение модели после preview требует нового плана.

## Настоящий заголовок вида

В `preview_finish_sheet` каждое изменение экрана задаётся независимо: масштаб, позиция, тип, текст заголовка, смещение или линия. Пример изменения только заголовка и типа:

```json
{
  "sheetId": 2798849,
  "viewports": [
    {
      "viewportId": 2801470,
      "viewportTypeId": 12345,
      "titleOnSheet": "В1",
      "labelOffsetXmm": 80,
      "labelOffsetYmm": 340,
      "labelLineLengthMm": 0
    }
  ]
}
```

`titleOnSheet` записывается в параметр **вида** «Заголовок на листе» (`VIEW_DESCRIPTION`). Для вида на нескольких листах текст изменится во всех его экранах. Пустая строка очищает переопределение заголовка. Видимость заголовка и линии определяется выбранным типом экрана.

`labelOffsetXmm` и `labelOffsetYmm` — компоненты `Viewport.LabelOffset`: вектор от нижнего левого угла экрана без поворота до левого конца линии заголовка. Это смещение в миллиметрах, допускающее отрицательные значения. При передаче одной компоненты вторая сохраняется. `labelLineLengthMm` передаётся в `Viewport.LabelLineLength`; ноль задаёт нулевую длину, отрицательное значение меняет направление линии. Заголовок остаётся частью экрана; текстовые примечания для него не создаются.

Существующие `xMm`/`yMm` в finish задаются парой **от нижнего левого угла `sheet.Outline`**, в отличие от абсолютных `centerXmm`/`centerYmm` нового размещения. Если позиция и масштаб отсутствуют, они сохраняются. При перемещении или изменении масштаба действует существующая проверка полей рамки: 20 мм слева и 5 мм с остальных сторон. Отдельное поле `notes` сохраняет создание обычных текстовых примечаний.

После preview примените `apply_finish_sheet` с `planId`. В обоих ответах `viewports` содержит фактическое состояние изменённых экранов, включая отдельные границы заголовков.

## Проверка в Revit

`node tests/sheet-layout-revit.mjs <fixture.json>` выполняет только чтение и preview с откатом в изолированном открытом проекте. Конфигурация должна содержать абсолютный `projectPath`, `processId`, `sheetId`, `unplacedViewId`, `placedViewportId` и `viewportTypeId`. `requireNegativeX=true` требует лист с отрицательным X. Вид должен допускать размещение, а экран — принадлежать выбранному листу. Скрипт проверяет центры, исходный ID вида, тип и заголовок, нулевую длину линии, откат при ошибке внутри пакета и неизменность ресурсов и количества элементов после preview.
