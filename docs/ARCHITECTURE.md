# Архитектура и MCP

[← Revit MCP](../README.md)

```text
MCP-клиент → stdio → Node.js → 127.0.0.1:37652 → ExternalEvent → Revit API
```

Node.js предоставляет MCP-инструменты и отправляет запросы локальной C#-надстройке. Мост слушает только IPv4 loopback и проверяет токен каждого запроса. Работа с Revit API выполняется в допустимом контексте через ExternalEvent.

| Назначение | Значение |
| --- | --- |
| Продукт / издатель | Revit MCP / OOXGN |
| DLL / namespace | RevitMCP.Loader.dll + RevitMCP.Core.dll / RevitMCP |
| MCP serverInfo.name | revit-mcp |
| Запись клиента | revit_mcp |
| TCP endpoint | 127.0.0.1:37652 |
| AddInId | 4D213781-9614-4BB6-9B2C-1F102A68B174 |
| VendorId | OOXG |
| Данные | `%LOCALAPPDATA%\RevitMCP` |
| Токен | `bridge.token` в каталоге данных |
| Настройки | `settings.json` в каталоге данных |
| Снимки | `snapshots/` в каталоге данных |

Переменная `REVIT_MCP_TOKEN` позволяет явно задать токен для собственного локального запуска сервера. Не включайте действующий токен в репозиторий, архивы или сообщения об ошибках.

Планы изменений связаны с документом и его ревизией. Срок действия — 10 минут. Изменение документа требует нового предпросмотра. Предпросмотр выполняет пробную операцию с откатом; `apply_*` повторно проверяет план и завершает транзакцию. Успешный ответ об изменении возвращается после commit.

Максимальный запрос — 1 МБ, ответ — 8 МБ. Для крупных наборов используйте страницы и ограничения соответствующего инструмента. Тайм-аут клиента рекомендуется задавать не меньше 320 секунд.

Чтение `query_stored_data` работает по локальным снимкам при закрытом Revit. Данные, возвращаемые MCP-инструментами, передаются выбранному MCP-клиенту.

## Обновление рабочей части

Постоянный загрузчик владеет лентой, TCP-мостом и ExternalEvent. Рабочая часть реализует `ICoreModule` и загружается из байтов в отдельный collectible AssemblyLoadContext. Между модулями передаются JSON-строки и объекты Revit API; собственные типы рабочей части за пределы контекста не выходят.

По кнопке загрузчик получает манифест выбранного канала. По умолчанию используется стабильный канал: `update.json` последнего опубликованного GitHub Release из `main`. Бета-канал включается отдельно и получает `updates/beta/manifest.json` с GitHub Pages. Выбор сохраняется в `Application/update-settings.json`. Отсутствие стабильного выпуска не включает beta автоматически.

Допускаются только пакеты этого репозитория по HTTPS, протокол 1, совместимая версия загрузчика, проверенные SHA-256 архива и каждого файла. Канал и исходная ветка проверяются по манифесту; адрес пакета должен соответствовать каналу, версии и SHA коммита. Состав ограничен DLL рабочей части и PNG-значками. Архив распаковывается в новый каталог, путь и размер каждого файла проверяются. SHA-256 обеспечивает целостность; доверие к источнику основано на HTTPS и правах публикации репозитория.

Загрузка показывает фактически полученные байты и процент. Проверка контрольной суммы и распаковка выполняются вне UI-потока; отмена проверяется при загрузке, распаковке и перед переключением. Ожидание свободного контекста Revit отображается отдельным этапом.

Переключение выполняется через ExternalEvent, после завершения выполняющейся операции Revit. Сначала проверяется новая DLL, затем атомарно записывается `Application/active.json` и меняется текущий модуль. Предыдущий путь сохраняется в `previous.json`. DLL установленной версии не перезаписывается. Очередь старых запросов отменяется; планы и ссылки старой рабочей части очищаются.

Каталоги `Application/versions/` содержат начальную установку, `Application/updates/<channel>/<commit>/` — пакеты обновления. Кеши stable и beta разделены, в том числе при выпуске одного коммита в обоих каналах. Загрузчик, Contracts, Updates и MCP-сервер остаются постоянными в пределах совместимого протокола. Изменения их контракта требуют установки нового загрузчика. Освобождение AssemblyLoadContext выполняется совместно с GC; накопленные внешние ссылки могут задержать сборку контекста. [Модель выгрузки .NET](https://learn.microsoft.com/en-us/dotnet/standard/assembly/unloadability).
