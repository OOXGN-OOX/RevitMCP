# Ожидаемые изменения при перезагрузке семейства

[← Разработка семейств](FAMILIES.md)

`preview_load_family` принимает необязательный массив `expectedChanges` для намеренного исправления существующих экземпляров. Требуется полный пакет `0.0.2` с загрузчиком `0.0.2.7` и сервером из той же сборки. После установки при закрытом Revit перезапустите MCP-клиент: горячее обновление рабочей DLL не меняет схемы сервера.

Сначала изучите `diagnostics.before`, `after` и полный diff отклонённого preview. Задайте точные ID, UniqueId и требуемые значения для каждого изменяемого экземпляра. Контракт проверяется после commit внутри отменяемой группы транзакций. Preview сохраняет его в плане вместе с SHA-256 RFA и ревизией проекта; `apply_load_family` принимает только `planId` и повторяет те же проверки. Изменение проекта, входного файла или несовпадение перехода требует нового preview.

```json
{
  "path": "C:/Families/Equipment.rfa",
  "parameterPolicy": "preserve",
  "sharedFamilySource": "file",
  "expectedChanges": [
    {
      "instanceId": 100,
      "uniqueId": "existing-instance-unique-id",
      "connectorClassifications": [
        {"connectorId": 1, "before": "SupplyAir", "after": "UndefinedSystemType"}
      ],
      "logicalSystemReferences": [{"connectorId": 2, "systemId": 200}]
    },
    {
      "instanceId": 110,
      "uniqueId": "existing-nested-instance-unique-id",
      "nestedType": {
        "before": {"family": "Equipment_Insert", "typeId": 501, "type": "Type A"},
        "after": {"family": "Equipment_Schedule", "type": "Type A"}
      }
    }
  ]
}
```

Замените значения примера данными текущего проекта. Один экземпляр задаётся один раз; пустой контракт и дубликаты отклоняются. Поддерживается до 500 экземпляров и до 200 коннекторов каждого вида в одной записи.

| Поле записи | Проверяемый переход |
|---|---|
| `instanceId`, `uniqueId` | Обязательная точная идентичность существующего экземпляра до и после загрузки. |
| `nestedType` | Точное прежнее семейство, typeId и имя типа → точные целевые семейство и имя типа. Допустимо только для вложений внутри проверяемого поддерева. ID нового символа выдаётся в полном diff: выделенный Revit ID в preview может отличаться от apply. |
| `connectorClassifications` | ID HVAC-коннектора и точные `before`/`after`: `SupplyAir`, `ReturnAir`, `ExhaustAir`, `OtherAir`, `UndefinedSystemType`, `Global`. Остальные свойства порта сохраняются. |
| `systemClassification` | Точные строковые `before`/`after` производного native-параметра «Классификация систем». Берите значения из снимка, учитывая язык Revit; пустая строка допустима, например после удаления последнего свободного электрического порта. Имя и тип системы не разрешаются к изменению. |
| `logicalSystemReferences` | ID коннектора и существующей MEPSystem. Допускается перенумерация единственной логической ссылки на эту же систему; её владелец, число ссылок и все физические ссылки сохраняются. |
| `removeUnconnectedElectricalConnectors` | Точный массив ID удаляемых электрических портов. У каждого до загрузки должны отсутствовать MEPSystem и все `allRefs`, а `isConnected` должен быть `false`. |

ID/UniqueId корневых FamilySymbol, ID/UniqueId экземпляров, их категория, родитель, размещение, отражения, физические соединения, ID/имя/тип систем и геометрия оставшихся портов обязательны к сохранению. Контракт не разрешает удаление экземпляров, замену корневого символа, добавление экземпляров или изменение неуказанных полей. Служебная смена FamilyId отражается отдельно. Без `expectedChanges` действует обычная строгая проверка с разрешёнными новыми вложениями.

Отчёт сохраняет все `changedInstances`, даже если их переходы ожидаемые. `preservation.expectedChanges` содержит проверенные записи, `passed` и причины несовпадения; `unexpectedChangedInstanceIds` перечисляет неподтверждённые изменения. При нарушении откатывается вся операция, а полный diff остаётся в `diagnostics.preservation`.
