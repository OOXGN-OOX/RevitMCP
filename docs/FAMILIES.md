# Разработка семейств

Инструменты работают с локальными RFA и RFT в Revit 2026. Документы открываются через `OpenDocumentFile` и `NewFamilyDocument`, без переключения пользовательских окон, и закрываются в `finally`. Уже открытый исходный RFA отклоняется. Изменения сохраняются только в новый файл; исходник производителя не перезаписывается.

## Инструменты

| Инструмент | Назначение |
| --- | --- |
| `get_family_authoring_options` | Идентификаторы типов данных, групп параметров и допустимых единиц |
| `read_family_file` | Категория, размещение, типы, параметры, геометрия, материалы, подкатегории, опорные плоскости, вложения и разъёмы |
| `read_family_type_catalog` | Заголовки TXT-каталога и строки с точным выбором по `rowName` |
| `preview_build_family` | Выполнение операций в скрытом документе, временное сохранение, повторное открытие и проверка |
| `apply_build_family` | Повторение проверенного плана и сохранение нового RFA |
| `validate_family_file` | Проверка сохранённого RFA; по запросу — испытание HVAC-соединений во временном проекте |
| `preview_load_family` / `apply_load_family` | Отдельная загрузка или перезагрузка в активный проект |

Для новой библиотеки инструментов нужен полный установщик с загрузчиком `0.0.2.2` и соответствующим MCP-сервером. Горячая замена рабочей DLL не обновляет схемы MCP. После установки перезапустите MCP-клиент.

## Чтение

`read_family_file` принимает `path`, необязательный список `typeNames`, `mesh` и `maxTriangles`. При отсутствии фильтра проверяются все типы. Для каждого возвращаются значения параметров, геометрия и разъёмы после регенерации. Если именованных типов нет, геометрия и разъёмы возвращаются в `untyped`. Определения параметров включают GUID общих параметров, тип данных, единицы, принадлежность типу/экземпляру, формулу, признаки `isReadOnly`, `isDeterminedByFormula`, `isReporting` и привязки к параметрам элементов.

Числовые значения сопровождаются `unitId`. Координаты, габариты и размеры разъёмов выражены в метрах; направления — безразмерные векторы. Система координат разъёма включает `origin`, `basisX`, `basisY`, `basisZ`. Геометрическое направление и направление потока возвращаются отдельно.

Геометрия содержит объёмы, плоские грани и габариты модельных форм и вложений, включая невидимые объекты. Пустоты и исходные формы внутри комбинаций не увеличивают итоговые габариты. Опциональная сетка ограничена `maxTriangles` на тип; `meshTruncated` сообщает о неполной сетке. Для больших семейств ограничивайте `typeNames`: транспорт допускает ответ до 8 МБ.

## Создание и редактирование

Передайте в `preview_build_family` ровно одно поле: `sourcePath` для существующего RFA или `templatePath` для RFT. `outputPath` должен указывать на новый RFA в существующей локальной папке. Укажите от 1 до 200 операций в порядке выполнения. Для сохранения нужен хотя бы один тип.

| Группа | Операции |
| --- | --- |
| Типы и параметры | `addType`, `renameType`, `addParameter`, `renameParameter`, `removeParameter`, `setValues`, `setFormula`, `importCatalogType` |
| Геометрия | `extrusion`, `cut`, `referencePlane`, `material`, `subcategory`, `setVisibility` |
| HVAC-разъёмы | `createHvacConnector`, `editHvacConnector`, `deleteElement`, `associateParameter` |
| Вложения | `loadNestedFamily`, `useNestedFamily`, `placeNestedFamily`, `setNestedType`, `setFamilyShared` |

Созданные элементы получают уникальный `key`. Последующие операции используют `{ "key": "body" }`; существующие элементы — `{ "id": 123 }` из чтения того же исходника. ID элементов предпросмотра не являются идентификаторами сохранённого файла: после записи прочитайте RFA заново.

`addParameter` принимает имя, `dataTypeId`, `groupId`, `isInstance` и необязательный `guid`. Наличие GUID создаёт общий параметр через временный файл определений; прежняя настройка файла общих параметров восстанавливается. `setFormula` принимает формулу либо `null` для её удаления. Формульные, отчётные и прочие параметры только для чтения нельзя назначать через `setValues`.

Значение задаётся одним из полей `value`, `materialName`, `elementId`. Измеряемое число требует совместимого `unitId` из `get_family_authoring_options`; материал должен существовать в семействе. После назначения выполняются регенерация и проверка значения.

`extrusion` принимает локальную систему координат `frame`, замкнутые многоугольные контуры `loops` и `depthMeters`. Последняя вершина автоматически соединяется с первой; дублировать её не нужно. `solid: false` создаёт пустоту. Для вырезания задайте `cut` с явными ссылками на тело и пустоту. Самопересечения, слишком короткие рёбра и недопустимые контуры отклоняет Revit.

Разъём создаётся на плоской грани, выбранной через `hostFace`: элемент, нормаль и, при неоднозначности, точку на грани. Формы — `Round`, `Rectangular`, `Oval`; системы — `SupplyAir`, `ReturnAir`, `ExhaustAir`, `OtherAir`; поток — `In`, `Out`, `Bidirectional`. Круглому разъёму нужен диаметр, прямоугольному и овальному — ширина и высота. `frame` задаёт конечную позицию и ориентацию, проверяемые после регенерации.

Перемещение ограничено плоскостью грани. Для изменения нормали можно выбрать другую грань или развернуть направление. Изменение формы существующего разъёма выполняется явным удалением и созданием с новыми привязками. `bindings` связывает встроенный параметр элемента с параметром семейства: например, `CONNECTOR_RADIUS` связывается с **радиусом**, а не диаметром. Формула `Diameter / 2` позволяет управлять радиусом через диаметр.

`loadNestedFamily` загружает новое вложение; `shared` меняет признак общего семейства во временной копии источника. Уже имеющееся вложение выбирается через `useNestedFamily` по `familyId`. Размещение поддерживает точку или указанную плоскую грань; доступность зависит от шаблона вложения. Можно выбрать тип, повернуть экземпляр и привязать параметры. Для существующего параметра с неоднозначным именем используйте встроенный идентификатор.

Удаление с зависимостями требует `allowDependentDeletion: true`. При запрете вся операция откатывается; список удаляемых ID возвращается в разрешённом предпросмотре.

## Каталоги типов

TXT читается с разделителем из первого символа заголовка. Поддерживаются UTF-8, UTF-16 и Windows-1251, BOM, поля в кавычках и удвоенные кавычки в дюймовых именах. `rowName` выбирает единственную точную строку с учётом регистра и пробелов; дублирующиеся имена отклоняются.

Импорт создаёт новый тип, преобразует единицы и проверяет значения после регенерации. Формульные, отсутствующие, неоднозначные, пустые и недоступные для записи поля возвращаются как `skipped` с причиной. Несовместимые единицы, некорректные числа и отсутствующие материалы останавливают пакет операций. Автоматическое создание материалов из произвольного текста каталога не выполняется. Синтаксис заголовков соответствует [описанию Autodesk](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-Customize/files/GUID-FFA71D72-D4C5-416D-BF65-1757657C3CE9.htm).

## Сохранение и проверка

Предпросмотр сохраняет RFA во временной подпапке целевой директории, закрывает его, открывает повторно и сравнивает определения параметров, типы, значения, геометрию и системы координат разъёмов. Временная папка удаляется. План действует 10 минут и содержит SHA-256 всех исходных RFA/RFT, каталогов, вложений и тестового RTE.

`apply_build_family` проверяет неизменность входных файлов, повторяет операции и проверки, затем перемещает проверенный RFA в `outputPath` без перезаписи. Отмена до перемещения не создаёт конечный файл. Эта операция не загружает семейство в рабочий проект.

`validation.expected` содержит проверки по `typeName`: значения параметров, `connectorCount` для HVAC и `sizeMeters` с допуском `toleranceMeters` (по умолчанию 0,0001 м). `testConnections: true` дополнительно создаёт скрытый проект, размещает каждый тип, проверяет число и полные системы координат HVAC-разъёмов, создаёт подходящие воздуховоды и вызывает `ConnectTo`. Связь проверяется через `IsConnectedTo`.

Для испытания соединений поддерживаются семейства на уровне и рабочей плоскости. Для второго варианта нужен план в `projectTemplatePath`. Если временный проект не содержит нужного типа воздуховода, передайте подходящий MEP-шаблон RTE. Семейства на стенах/потолках, по линиям и адаптивные требуют отдельных испытательных хостов; текущая проверка их отклоняет. Отсутствие разъёмов или неподдерживаемый способ размещения не считаются успешным испытанием.

Перезагрузка в проект требует явных `parameterPolicy` (`rejectExisting`, `preserve`, `overwrite`) и `sharedFamilySource` (`project`, `file`). Сначала выполните `preview_load_family`, затем `apply_load_family`. Политика `preserve` сохраняет значения параметров по правилам `IFamilyLoadOptions`; она не запрещает обновление геометрии семейства.

Вращения, переходы и геометрия по траекториям пока отсутствуют. Автоматическое построение параметрических размерных зависимостей между гранями и опорными плоскостями также не входит в этот набор.
