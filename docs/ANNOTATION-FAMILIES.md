# Аннотационные семейства, метки и 2D-графика

[← Разработка семейств](FAMILIES.md)

Платформа — Revit 2026. Инструменты требуют полного пакета `0.0.2` с загрузчиком `0.0.2.10` и MCP-сервером из той же сборки. Установка выполняется при закрытом Revit; затем перезапустите MCP-клиент. Обновление одной рабочей DLL не меняет схемы сервера.

## Каталог операций

`get_family_operation_catalog` работает без запущенного Revit. Без аргументов он возвращает список 34 операций, примеры, категории, единицы и ограничения. Вызов с `{"action":"annotationText"}` возвращает полную JSON Schema выбранной операции и пример. Схема берётся из той же реализации, которая проверяет `preview_build_family`; структура доступна независимо от отображения union-типов клиентом.

Примеры содержат условные ID. Выбирайте реальные ID видов, стилей и элементов из чтения RFA. Условия, проверяемые Revit или дополнительными правилами схемы, перечислены в `constraints` и `notes`; наличие действия в каталоге не означает поддержку любой категории RFT.

## Чтение семейства

`read_family_annotations` скрыто открывает RFA, при необходимости переключает `typeName`, регенерирует документ и возвращает:

- `resources`: виды и их оси, типы текста, типы областей, стили линий, образцы заливки и GUID общих параметров;
- `annotations.elements`: доступные TextElement/Label, TextNote, кривые, области и размеры с ID/UniqueId, типами, параметрами и геометрией;
- положение, ширину, высоту и выравнивание текста; границы областей; ссылки и параметр семейного размера;
- `errors`, `hasMore`, `offset`, `limit` для контроля полноты.

Используйте `viewId` для одного вида и страницы до 500 элементов. Координаты геометрии возвращаются в метрах; `localPosition` текста — в миллиметрах относительно начала и осей вида. `read_family_file` также включает снимок аннотаций каждого типа, а сохранение через build проверяет его после повторного открытия. Предел такого снимка — 5000 элементов; `hasMore` или `errors` означают неполную проверку.

## Label в Revit 2026

Публичный API этой версии не раскрывает состав подписи Label: порядок параметров, их членство по GUID, префиксы, суффиксы, разделители, переносы и формат единиц каждого поля. Создание Label и изменение этого состава инструментами не поддерживается. Это отражено как `labelComposition.available=false` и в возможностях каталога.

Существующие метки читаются как TextElement с доступными свойствами. `labelCandidate=true` обозначает TextElement, который не является TextNote; это не восстановленный состав подписи. GUID общих параметров семейства перечисляются отдельно и не доказывают использование параметра в метке. Состав подписи не выводится из совпадений её текста со значениями элементов.

Для существующей метки доступны положение, ширина, выравнивание и смена совместимого текстового типа через `editAnnotationText`. `annotationTextStyle` дублирует исходный TextElementType и задаёт шрифт, высоту, начертание и фон. Поле `text` разрешено только для постоянного TextNote; попытка заменить им содержимое Label отклоняется. Для состава подписи используйте заранее подготовленное RFA/RFT с нужной меткой и сохраните её при остальных изменениях.

## Построение и параметризация

Операции выполняются в `preview_build_family`, сохраняются во временный RFA и проверяются после открытия. Новый выходной RFA записывается только через `apply_build_family`; исходник не перезаписывается.

| Операция | Назначение |
|---|---|
| `annotationCurve`, `editAnnotationCurve` | Линия, дуга по трём точкам или окружность; создание detail/symbolic и изменение существующей кривой. |
| `annotationLineStyle` | Новая подкатегория со штриховкой линии, цветом и весом 1–16; применение через `lineStyle`. |
| `annotationTextStyle` | Новый текстовый тип на основе существующего; исходный тип не изменяется. |
| `annotationText`, `editAnnotationText` | Постоянный текст, ширина и выравнивание; для существующих Label — только доступные свойства оформления. |
| `annotationRegionStyle` | Дубликат типа области с образцами и цветами заливки, весом линии. |
| `annotationRegion` | Заливка или маска по замкнутым контурам из линий, дуг и окружностей. Заливке нужен `regionType`. |
| `replaceAnnotationRegion` | Новая область вместо старой с явной сменой ID; зависимые удаления требуют `allowDependentDeletion`. |
| `annotationDimension`, `setAnnotationDimension` | Размер между опорными плоскостями/кривыми; FamilyParameter и блокировка, если Revit разрешает такие зависимости. Это размерный параметр, а не состав Label. |

`viewId` обязателен для геометрии и текста. `xMm`/`yMm` задаются в плоскости вида вдоль Right/Up от его Origin, в миллиметрах на бумаге. В RFA используется масштаб 1; в проекте координаты переводятся через масштаб вида. Ширина текста и высота шрифта остаются бумажными размерами. Контуры должны быть плоскими, замкнутыми и не пересекаться; допустимость проверяет Revit.

Ссылки `{ "key": "…" }` обращаются к результатам предшествующих операций, `{ "id": 123 }` — к существующим элементам. Для видимости используйте `associateParameter` с доступным native-параметром, например `IS_VISIBLE_PARAM`, и Yes/No-параметром семейства. `setFormula`, типы и значения работают вместе с параметризованными размерами. Не каждый элемент допускает привязку или блокировку; отказ Revit отменяет построение.

## Образцы и изображения

`validate_annotation_family` загружает RFA в закрытый отдельный образец `sampleProjectPath` (RVT без совместной работы). Для каждого `samples` задаются `viewId`, `scale`, `typeName`, `elementIds` и необязательные `parameters`: ID цели, имя/область параметра и строковое значение. Так можно подготовить варианты с длинными, пустыми и многострочными значениями.

Инструмент создаёт IndependentTag на заданных элементах и экспортирует PNG в новую подпапку `directory`. Результат содержит текст марок, геометрию, `empty` и `unresolved`, а также пути изображений. RFA и RVT закрываются без сохранения, их контрольные суммы проверяются. Уже открытый RVT и совместная работа не допускаются. Значения исходного образца должны быть доступны для записи; управляемые формулой поля не обходятся.

Изображения получаются из Revit. Признаки пустого/неразрешённого текста не являются проверкой состава Label или автоматическим анализом читаемости. Просмотрите PNG при нужных масштабах и значениях; совпадение снимков и успешная компиляция не подтверждают качество оформления. RoomTag, SpaceTag, марки связей и визуальная проверка Generic Annotation этим сценарием не охватываются.

## Существующие марки и аннотации проекта

`read_tags` возвращает состояние IndependentTag и `documentRevision`: голову, ориентацию, текст и каждую привязку с `referenceIndex`, стабильной ссылкой, изгибом и свободным концом. Передайте ревизию и изменения в `preview_edit_tags`, затем `apply_edit_tags`. Конец выноски изменяется только при `leaderEndCondition="Free"`; закреплённые/сгруппированные марки и ссылки на связанные модели отклоняются. Привязки добавляются перед удалением старых; после commit проверяется итоговое множество ссылок и состояние марки. Операция не меняет состав Label семейства.

`get_view_annotation_resources` возвращает стили и типы Generic Annotation. `read_view_annotations` читает геометрию существующего оформления вида. `preview_edit_view_annotations` / `apply_edit_view_annotations` используют те же annotation-операции для текста, кривых и областей, а `placeGenericAnnotation` размещает выбранный view-based тип с позицией и углом. Символические кривые и параметризованные семейные размеры остаются операциями RFA. Новые ID из preview временные.
